# 报告分流与技术可行性报告流程

## 先分流（写错层等于白写）

| 报告类型 | 特征 | 路径 |
|---|---|---|
| ① 领域导读报告 | 给人快速入门一个领域：一分钟入门、术语表、发展分期、奠基论文、主线脉络、必读清单、开放问题 | `fill_domain_report`（你提供全部内容，引用只能用图谱内论文 id）→ `emit_result` 渲染 |
| ② 轻量综述 / 方向盘点 | 你一轮综合即可完成，不需要逐段查证 | 写好正文 → `save_report` → `export_report_pdf` |
| ③ 技术可行性报告 | 决策文档：判断某个研究想法值不值得投入 | 下面的六步流程，**你自己跑全程** |

用户提"深度报告""可行性""立项级"时一律走 ③。③ 不要用 ② 的方式一轮写完——那样产出的是观点堆砌，不是决策依据。

## 技术可行性报告六步（一个想法一份，环节一个不能少）

### 1. 查重

拆出想法的核心技术组合词，三路并行撞车：`find_candidates`、`search_recent`、你原生的 WebSearch。逐条判断重合度，弱相关的是检索噪声可以过滤。**检索为空只说明没检出，不能写成"无相关工作"**。撞上强相关工作时：回改想法（`fill_research_idea` 同标题覆盖）或在报告里明写差异化。

### 2. 对抗评审

起独立子 agent 扮三个怀疑者轮番攻击这个想法：
- 新颖性怀疑者：这跟已有工作到底差在哪
- 技术成立性怀疑者：核心假设站得住吗，机制上有没有硬伤
- 实验设计怀疑者：预测可证伪吗，指标有操作定义吗，统计效力够吗

外加可执行性评估五个维度：外部仓库依赖、预训练权重可得性、GPU 资源、数据获取难度、胶水代码复杂度 → 定级为轻 / 中 / 重。评审出的问题先就地改想法，不要带着问题进写作。

### 3. 逐段查证写作（只用 `save_report_section`，一轮一节）

报告骨架固定五章，小节标题必须带 `N.M` 编号，章标题/排序/层级由工具自动组装：

1. **背景与动机**——1.1 问题陈述（当前短板的量化证据）/ 1.2 相关工作（逐流派对比）/ 1.3 根本性分析（第一性原理层面说清为什么现有方案不行）
2. **方法**——2.1 系统总览（贡献列表）+ 逐贡献一节（公式、代码块、精确到可直接改代码的粒度）+ 推理/使用流程
3. **实验计划**——评估指标（现值/目标值表）/ 消融实验设计（分组编号 A/B/C）/ 基线方法 / 数据集要求（含预处理与耗时估算）/ 计算资源估算表
4. **可行性评估**——实现复杂度（对比替代方案）/ 外部依赖风险表（风险级别+缓解策略）/ 错误传播风险 / 时间线与里程碑表 / 综合可行性判断（评级+有利不利因素+建议决策路径）
5. **结论**——一段收束（可传 `5. 结论` 章级直书，尾注完成日期/目标系统/风险等级）

「要不要做/怎么做/代价多少/坏了怎么办」是校验维度不是章名：要不要做落在 1.2/1.3 与 4 章综合判断，怎么做落在 2 章，代价落在 3 章资源估算与 4 章复杂度，坏了怎么办落在 4 章风险小节。

每节写之前先取证再写，`evidence_refs` 要能对上图谱论文 id / 卡片 / 原文库文件 / repo 卡。**代码级论断（实现复杂度、硬编码参数、改造接入点）必须来自 repo 卡**：先用你的 Bash 浅克隆目标仓库（`git clone --depth 1`）、Read/Grep 实读，`fill_repo_card` 落卡（文件:行号 证据 ≥3 处）后引用——凭模型记忆写会被拒。查不到出处的事实一律标『待验证』，不许编。一轮只交一节（正文含 ##/### 会被拒）；缺必备小节时 `export_report_pdf` 会列清单拒绝出版。

### 4. 审校

起**另一个**子 agent，视角与写作者对立，通读报告逐条出问题清单：P0（编造或事实错误，必须改）/ P1（论证缺口）/ P2（表述），附总评结论。用 `save_review` 落盘。没有审校记录时，`export_report_pdf` 会拒绝出版。

### 5. 修订

P0/P1 逐条核实来源后改，`save_report_section` 同标题节就地替换。只有结构性缺陷才整篇重写。**修订有预算：同一份报告的审校-修订循环不超过两轮**——两轮后仍有 P0，说明问题在想法本身而不是文字，退回去改想法（第 1 步的差异化或回改），不要在报告层无限打磨。

### 6. 出版

`export_report_pdf`。多份报告严格串行导出。

## 多想法批量

开始前先做一轮优先级分流：每个想法按"预期收益（撞车少+证据链强）× 成本（可执行性五维定级）"打分排序，先做高分的；全部完成后可另用 `save_report` 出一份带优先级对比的方向盘点索引。依次走完一个想法的 1-6 再开始下一个，不要并行交叉写多份报告。

## 运维

- `citecoon pdf <报告名> -p <项目>` 可在终端给存量报告补导 PDF
- `project_status` 看项目推进度；`citecoon doctor` 体检环境；密钥在 `~/.citecoon.env`
