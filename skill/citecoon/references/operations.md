# 运维协议：恢复、委派、拒绝、预算

跨场景通用的操作规程。各场景文档在对应环节引用本文。

## 1. 中断恢复协议（新会话 / 上下文被压缩后）

落盘产物就是断点——恢复靠盘点产物，不靠回忆对话。固定四步：

1. **重建概览层**：`project_status`（资产计数、idea 评审状态、报告审校判定、最近变更）+ `graph_summary`（图谱规模、断连节点）。没有概览层就发现不了跨源关联，别跳过。
2. **产物对账**：`list_papers`（only_uncarded=true 看待落卡清单）+ `list_idea_cards`。papers/ 里有原文但没卡片的 = 精读欠账。
3. **续点定位**：从概览的"最近变更"确定上次停在哪一环节（建图中 / 落卡中 / 报告第 N 节 / 审校待修订），直接续跑该环节。
4. **标识符逐字保留**：paper_id、arXiv 号、文件路径这类标识符必须原样使用，压缩最容易丢的就是它们和"为什么这么做"的理由——恢复时若发现理由缺失，先重新取证再动手，不要脑补。

中断前的主动动作：关键判断（seed 的 rationale、已证伪的路径、阶段结论）随手落盘或 take_note，不要只留在对话里。

## 2. 子 agent 委派契约

**委派白名单**（满足才委派）：
- 批量全文精读（每个子 agent 只装 1 篇论文的上下文，产出卡片字段级要点）
- 独立对抗审校（必须拿不到写作思路才叫独立）

**不委派**：复述已有卡片、改写已有结论、单个工具调用序列。

**任务书必须自包含**（子 agent 看不到你的上下文）：给它该看的素材清单（paper_id / 文件路径）+ 明写不许看什么 + 验收标准。回传契约是结构化结论（按 fill_idea_card 字段组织），不是原文摘录——大体积中间信息根本不进主上下文。

**落盘闸门留在你手里**：子 agent 产要点，你校对后自己调 fill_idea_card 落盘。一批最多 3 个子 agent，不够就分批。

## 3. 如何消费工具拒绝

拒绝是回路不是终点：读拒绝消息说的"缺什么、怎么改"，补齐后重提。禁止的应对：换措辞原样硬闯、拆成多次绕阈值、自建编号绕过。同一调用以同样方式被拒两次，说明理解有偏差——停下重读取证，不要第三次重试。

## 4. 预算读数 → 动作（不要只读不动）

| 读数 | 动作 |
|---|---|
| 同一查询两次零命中 | 缩短 query 或降级逐词 AND；第三次原样重试无效 |
| 提示"疑似限流" | 等待后重试同一查询（空结果可能是假的），不要换词 |
| read_paper 返回落盘路径 | 后续引用用 read_fulltext 定点读，不重复拉全文 |
| 批量精读 > 8 篇 | 改分工模式：子 agent 读盘产要点，你落卡 |
| 卡片数 ≥ 图谱 1/3 且母题未归纳 | 先 save_themes 再提 idea，跳过母题的想法缺证据链 |

## 5. 经验升级政策

- 记录与整理分离：take_note / 落卡是即时追加；归纳通用规则放独立阶段，且要多卡支撑——单次成功不许直升为纪律。
- 同一纪律被反复违反时，优先反馈给工具维护方做成 schema 校验/拒绝（工具闸门 100% 有效，手册文字会被无视），其次才是改本手册。
- 改手册走最小 diff：先定位失败场景，只改对应段落，改完用旧场景回归（尤其"已下线工具名清单"这类防回归内容不能被破坏）。
